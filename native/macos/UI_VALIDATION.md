# UI刷新の検証手順

## 検証用サーバー

```sh
npm run build
.venv/bin/python scripts/ui-fixture-server.py --port 8877
```

`http://127.0.0.1:8877/?scenario=idle`で画面を開きます。サーバーは127.0.0.1だけに公開し、Python標準ライブラリだけを使用します。録音・文字起こし・クリップボード・フォルダ操作・更新インストールはすべて模擬応答です。実際の会議データや設定には触れません。`dist`を静的配信するため、フロントエンド変更後は再ビルドしてください。fixtureコードは配布アプリに含めません。

`scenario`を変えて新しくページを読み込むと状態を初期化できます。状態はサーバー全体で共有するため、検証は1ウィンドウずつ順番に行います。補助API `POST /__fixture/scenario`（本文 `{"scenario":"complete"}`）でも初期化できます。イベントIDは単調増加し、`since`指定より新しいイベントだけ返します。

| シナリオ | 確認対象 |
| --- | --- |
| idle | 初期状態、標準モデル、録音開始 |
| starting | 権限案内、二重開始不可 |
| recording | 経過時間、停止操作、入力の変更禁止 |
| processing | 文字起こし中の説明、入力の変更禁止 |
| complete | 保存先、生成結果、コピー操作 |
| error | エラー理由、保存済み音声、小さいモデルでの再実行 |
| closing | 録音中から「保存して終了」を押した後の終了待機表示 |
| loading | API応答を12秒遅延、読み込み表示と開始禁止 |
| empty | マイク・システム音声の一覧が空の場合の表示 |
| long | 長い日本語デバイス名・保存パスの折り返し |
| windows | 処理デバイス・CUDA・更新機能を保持 |

録音開始を押すと準備中→1.5秒後に録音中になります。停止または既存フォルダ文字起こしを押すと、マイク→システム音声→文字起こし生成→プロンプト生成→完了が約4.3秒で進みます。終了APIは成功を返しますが、fixtureサーバーは終了しません。

| 従来の機能 | 新しい配置 |

| デバイス再取得・一覧 | ヘッダーの設定→「音声デバイス」 |
| macOS権限の再確認 | 設定→「macOSのアクセス許可」 |

ソース上の配置確認です。操作成功や外観の検証結果は下記記録と区別します。

## 機能維持チェックリスト

- [ ] 新規録音と既存フォルダ文字起こしをそれぞれ実行できる。
- [ ] マイク選択、システム音声選択、デバイス再取得が利用できる。
- [ ] MacはApple Silicon固定、5モデルとlarge-v3-turbo標準を維持。
- [ ] 保存先の参照・変更と既存フォルダ選択が利用できる。
- [ ] 完了結果の保存先を開く操作とプロンプトコピーが利用できる。
- [ ] タブ切り替えで完了結果や選択済みフォルダを失わない。
- [ ] エラー時は失敗した録音の保存先が再実行対象となり、前回の成功結果と混同しない。
- [ ] 録音準備中・録音中・処理中・終了中の操作禁止が一貫している。
- [ ] 権限再確認、保存して終了、WindowsのCUDA・更新操作を保持。
- [ ] ライト・ダークの両方で文字、選択欄、フォーカス、警告が読める。
- [ ] 1040×840・860×640・1440×900・幅390の縦画面で横にはみ出さず、主要操作に到達できる。
- [ ] キーボードだけで設定を開閉でき、Escapeとフォーカス復帰が機能する。
- [ ] 閉じる前のAPI応答、イベントの重複、失敗後のprocess_closedで状態が逆戻りしない。
