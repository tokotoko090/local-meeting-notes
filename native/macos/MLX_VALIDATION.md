# MLX Whisper 実機検証

2026年9月18日、Apple M2 / メモリ16GBのMacで実施。

## 条件

- macOSのKyoko音声で生成した日本語15.545秒。個人の録音は使用していません。
- 同じ音声の前後に35秒ずつ無音を付けた85.545秒、および完全無音10秒も検証。
- 入力は16kHz・モノラルPCM16。MLXはGPU・FP16、日本語指定。
- 初回推論と、その後3回の推論時間の中央値を区別。モデル取得、モデル読み込みは推論時間に含めません。
- CPU比較はfaster-whisperのbase / int8 / beam_size=1 / best_of=1 / VAD有効。

参照文:

> 本日の会議を始めます。新しいアプリの公開日は来月十五日です。田中さんは画面の確認を、佐藤さんは資料の作成を担当します。次回の会議は金曜日の午後三時からです。

## 開発環境での結果

時間の単位は秒。取得欄はキャッシュ解決と必要なダウンロード、読み込み欄はGPUへのモデル読み込み・評価・同期を含みます。

| MLXモデル | 取得 | 読み込み | 初回推論 | 追加3回の中央値 |
| --- | ---: | ---: | ---: | ---: |
| base | 0.142（取得済み） | 0.105 | 0.440 | 0.269 |
| small | 0.162（取得済み） | 0.400 | 1.104 | 0.689 |
| medium | 124.975 | 4.434 | 6.520 | 3.773 |
| large-v3 | 217.820 | 2.628 | 4.475 | 3.835 |
| large-v3-turbo | 120.192 | 0.849 | 1.937 | 1.355 |

baseとsmallは無音対策前に取得済みのため、最終測定はキャッシュを使用しました。large-v3は取得のみを先に実行し、推論を別プロセスで測定しました。medium測定時は他のビルド作業も行われていたため、他モデルとの厳密な速度比較には使用できません。各「初回推論」は新規プロセス内の最初の推論であり、Metalのコンパイル済みキャッシュが存在する場合があります。実験全体で最初のbase GPU推論は2.360秒でした。

全5モデルで参照文の内容を認識し、10秒の完全無音は空の結果になりました。長い無音を含む入力も、発話前後に架空の文章を生成しませんでした。実際の発話は35秒から始まり、返却された最初の時刻は34.8秒でした（無音除外の余白を含む）。句読点、漢数字・算用数字、区切り方に差があります。

ビルド作業・他の推論を止め、同じbaseモデル・同じ日本語音声でCPU、GPUを順に再測定した結果:

| 実行方式 | モデル読み込み | 初回推論 | 追加3回の中央値 |
| --- | ---: | ---: | ---: |
| faster-whisper CPU / int8 | 0.294 | 0.855 | 0.802 |
| MLX GPU / FP16 | 0.105 | 0.440 | 0.269 |

この条件では推論の中央値が約2.98倍高速でした。両方式とも参照文の内容を認識しました。既にモデルを取得済みの比較であり、初回ダウンロード時間は含みません。

## 完成したMacアプリでの確認

`release/Local Meeting Notes-darwin-arm64/Local Meeting Notes.app`を再ビルドし、署名を検証しました。アプリ起動と配信画面で、5モデル、初期値`large-v3-turbo`、処理デバイス選択がなく「Apple Siliconで処理」と表示されることを確認しました。

アプリに同梱した実行ファイルを使い、`HF_HUB_OFFLINE=1`、`PATH=/usr/bin:/bin`、作業場所を一時フォルダにして確認しました。開発用PythonやHomebrewの実行ファイルを参照せず、取得済みモデルで動作しました。

- `base`と`large-v3-turbo`でマイク音声・PC音声の2ファイルを順次処理し、両方とも`runtime_device=mlx`・`compute_type=float16`でした。
- 旧形式の`cpu`指定もMLXで実行され、言語確率は`null`でした。
- 長い無音を含む音声でも元録音基準の時刻を維持し、文字起こしとChatGPT用Markdownを生成しました。
- 起動・読み込み・音声変換・2ファイルの推論・出力を含めた所要時間はbase 6.403秒、turbo 5.388秒でした。上の推論単体の値とは測定範囲が異なります。
- APIが5モデル・MLX固定・turbo初期値を返し、正常終了することを確認しました。自動テスト23件、HTTP検証、フロントエンドビルドも成功しました。

配布時にMLXのC++拡張が内部で読み込むモジュールが不足する問題を検出し、明示同梱で修正したうえで上記を再検証しました。

## 再実行

```sh
.venv-mlx/bin/python scripts/benchmark-mlx.py --engine mlx --model base
.venv/bin/python scripts/benchmark-mlx.py --engine cpu --model base
.venv-mlx/bin/python scripts/smoke-mac-mlx.py
```

`--model`を変更して各モデルを検証できます。JSON結果と合成音声は`build/mlx-validation/`に出力されます。初回の音声生成はmacOSの音声合成へのアクセス、GPU検証はMetalへのアクセスが必要です。制限された実行環境では許可が必要になります。

## 解釈上の制限

合成された明瞭な短い日本語音声での検証です。実際の長時間会議、複数人の同時発話、雑音、専門用語での精度や速度は保証しません。初回のMetalコンパイル、バックグラウンド作業、メモリ使用状況で所要時間が変わります。

MLXの無発話判定だけでは長い完全無音に架空の文章が出たため、ほぼデジタル無音の区間をスキップする処理を追加してから再検証しました。時刻は元音声基準のままです。この処理は環境雑音を含む無発話区間をすべて検出するVADの代わりではありません。
